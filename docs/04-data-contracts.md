# 04 · Data contracts

> The stable JSON contracts that flow between the agents, and the Excel mapping. These contracts are the
> reason the pipeline survives long runs — see [chapter 05](05-deterministic-output-pattern.md) for *how*
> they are enforced.

## 4.1 Rule page (Extractor → Analysts)

The extractor returns a stable page of up to five rules:

```json
{
  "pack": "<rule pack name>",
  "country": "<target country>",
  "from": 1,
  "to": 5,
  "total": 200,
  "count": 5,
  "rules": [
    {
      "rule_id": "<store row id>",
      "rule_identifier": "<stable business id>",
      "code": "AAA.01.L2",
      "area": "<area>",
      "level": "L2",
      "text": "<rule statement>",
      "issue": "<short issue label>",
      "reference_wording": ""
    }
  ]
}
```

`reference_wording` is an **analyst input** (a remediation hint). It is never legal evidence and is never
copied into a result field.

## 4.2 Analyst results envelope (Analyst → InsertXls)

```json
{
  "campaign": "<audit name>",
  "document": "<contract file name>",
  "pack": "<rule pack name>",
  "comparison": "Internal | <target country>",
  "country": "<empty for Internal | target country for Country>",
  "count": 5,
  "results": [
    {
      "rule_id": "<id>",
      "rule_identifier": "<id>",
      "code": "<rule code>",
      "area": "<area>",
      "level": "<level>",
      "issue": "<issue>",
      "rule": "<rule text>",
      "comparison": "Internal | <target country>",
      "status": "Conformant | Non-conformant | Not found | To verify",
      "evidence": "<contractual and, when relevant, country evidence>",
      "analysis": "<reasoning>",
      "confidence": "High | Medium | Low",
      "qualification": "<targeted qualification>",
      "remediation": "<suggested wording when justified>",
      "source_url": "<exact contract URL>"
    }
  ]
}
```

### Required invariants

- `count == results.length`, and `count` is between 1 and 5.
- Exactly **one** result per rule in the current page.
- Root and rule metadata are **copied from the inputs**, not regenerated by the model.
- Every `source_url` is **identical** to the contract URL supplied to the analyst (never rewritten).
- Internal: root `comparison = "Internal"`, root `country = ""`.
- Country: root `comparison` and `country` both equal the target country.
- **No** Markdown or prose surrounds the final JSON.

## 4.3 Status vocabulary

| Canonical value | Meaning |
| --- | --- |
| `Conformant` | The rule is satisfied |
| `Non-conformant` | The rule is not satisfied |
| `Not found` | The contractual element is not present |
| `To verify` | A material uncertainty could change the conclusion |

> **Field note.** In practice the model sometimes emitted localized aliases (e.g. a French equivalent of a
> status) inside what is meant to be a machine contract. The skill scripts **normalize** accepted aliases
> to the canonical English values before emission. See
> [chapter 06 · language & output drift](06-harness-limits-field-notes.md).

## 4.4 Excel mapping (19 columns)

Each result object maps to exactly one row in `InternalResults` or `CountryResults`:

| Excel column | JSON source |
| --- | --- |
| Campaign | root `campaign` |
| Document | root `document` |
| Pack | root `pack` |
| Country | root `country` |
| Rule ID | `result.rule_id` |
| Rule Identifier | `result.rule_identifier` |
| Rule Code | `result.code` |
| Area | `result.area` |
| Level | `result.level` |
| Issue | `result.issue` |
| Rule | `result.rule` |
| Comparison | `result.comparison` |
| Status | `result.status` |
| Evidence | `result.evidence` |
| Analysis | `result.analysis` |
| Confidence | `result.confidence` |
| Qualification | `result.qualification` |
| Remediation | `result.remediation` |
| Source URL | `result.source_url` |

The insertion agent adds **result rows only** — it never creates sheets, columns or headers, and never
exposes technical notes in the human‑facing workbook.
